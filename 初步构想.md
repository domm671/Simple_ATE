ATE测试软件本质是在ATE/FT测试机器上编制测试脚本流程，并通过CAN或RS485等通讯方式下发给下位机测试装备进行测试，得到返回结果后记录结果。

我想要的ATE软件的软件名为simple_ATE，仅包含UI、通讯、脚本引擎（解析与执行器）、日志记录、MES接入。

**simple_ATE** 应该刻意保持“小”。

现在定义的：

```text
simple_ATE
│
├── UI
├── 通讯
├── 脚本引擎（解析与执行器）
├── 日志记录
└── MES 接入
```

已经足够构成一个完整的 ATE/FT 上位机软件。

关键在于：**不要为了“通用”而一开始就做成庞大的平台。**

# 2. Script Engine 

脚本不需要一开始设计得特别复杂。

脚本使用xml自定义标签，python解析脚本后执行对应的python代码逻辑。

以后再逐步增加：

```text
v0.1
├── 顺序执行
├── 调用通信
├── PASS / FAIL
├── timeout
├── retry
├── if
├── loop
├── delay
└── sub-script
```

我非常建议这样演进。

**不要第一版就实现 DSL 编译器、AST、复杂语法树。**

# 3. Communication

通信层最好独立。

例如：

```text
communication/
│
├── can.py
├── serial.py
├── tcp.py
└── base.py
```

统一接口：

```python
class Communication:

    async def connect(self):
        pass

    async def disconnect(self):
        pass

    async def send(self, data):
        pass

    async def receive(self, timeout):
        pass
```

然后：

```python
can = CANCommunication(...)
serial = SerialCommunication(...)
```

```

底层实际可能是：

```text
bms.read_voltage
        ↓
BMS Driver
        ↓
CAN
        ↓
python-can
        ↓
CAN Hardware
```

# 4. Logger

日志建议分成两类。

## Runtime Log

用于查看程序运行：

```text
12:00:01 INFO Test started
12:00:02 INFO CAN connected
12:00:03 INFO Send: 0x18FF50E5
12:00:03 INFO Receive: 0x18FF50E5
12:00:04 INFO Voltage = 12.03
12:00:05 PASS Voltage Test
```

## Test Result

用于记录正式测试结果：

```json
{
    "sn": "BMS20260909001",

    "script": "BMS_FT",

    "result": "PASS",

    "items": [
        {
            "name": "Voltage",
            "value": 12.03,
            "unit": "V",
            "result": "PASS"
        }
    ]
}
```

我建议这两个不要混在一起。

# 5. MES

MES 应该只是一个 Adapter。

```text
Test Engine
     │
     ▼
Test Result
     │
     ├── Local Storage
     │
     └── MES Adapter
              │
              ├── HTTP
              ├── TCP
              └── Database
```

例如：

```python
result = await engine.run(script)

await mes.upload(result)
```

不要让脚本里出现：

```yaml
- action: upload_mes
```

除非某个特殊流程真的需要和 MES 进行中途交互。

一般情况下：

```text
MES 查询产品信息
        ↓
运行测试
        ↓
生成 TestResult
        ↓
上传 MES
```

即可。

## simple_ATE 的真正核心可以非常简单

实际上可以概括成：

```text
UI
 │
 │ Start
 ▼
Load Script
 │
 ▼
Execute Step
 │
 ├── Communication
 │
 ├── Judge
 │
 ├── Log
 │
 └── Save Result
 │
 ▼
Next Step
 │
 ▼
Finish
 │
 ├── Local Log
 └── MES
```

 **simple_ATE 设计理念：

> **Simple to understand.  
> Simple to configure.  
> Simple to extend.  
> Simple to deploy.**

如果继续往下推进，我建议下一步直接确定 **simple_ATE V0.1 的脚本格式**。

整个软件的核心接口：

```text
Script
   ↓
Parser
   ↓
Step
   ↓
Executor
   ↓
Communication
   ↓
Result
```
